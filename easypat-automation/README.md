# EasyPAT HTTPS 자동화

목표는 마우스 이동 없이 EasyPAT의 HTTPS 통신으로 사건 조회, 문서 다운로드·정보 추출을 수행하고 마지막에 업무 함수를 MCP 도구로 제공하는 것이다. Fiddler와 화면 조작은 개발 중 기존 캡처를 확인하는 용도로 사용한다.

## 현재 상태

- 자동 로그인 성공 경로는 실제 계정으로 한 번 검증했다. 고정된 HTTPS POST 2건에서 사용자 ID 일치, 권한 8행, JSESSIONID 수신을 확인했고 쿠키와 자격 증명 값은 출력·저장하지 않았다.
- 인증 어댑터는 런타임에 연결되어 있지만 한 프로세스에서 로그인은 최대 한 번이며, 실패 응답 의미와 세션 갱신은 아직 비활성이다.
- P261793 본문 조회의 통제된 시도는 실패 후 자동 재시도 없이 종료되었다. 당시 Fiddler 캡처가 꺼져 있어 실패 단계와 실제 요청 수는 확정할 수 없다.
- 내부키 응답 검증을 추가한 두 번째 통제된 시도는 자동 로그인과 SELECT 응답 수신 후 결과 파서에서 종료됐다. 기존 캡처 메타데이터로 한글 열 이름 5개와 `timestamp` 타입이 원인임을 확인해 관찰된 규격만 허용하도록 파서를 수정했다. 이 시도도 자동 재시도와 서버 수정은 없었다.
- 파서 수정 후 별도 1회 게이트로 다시 검증해 1행·205열 응답과 고정 SELECT 조건의 `idx`가 정확히 일치함을 확인했다. 원문 행·내부키·쿠키는 반환하거나 저장하지 않았다.
- 운영 허용 목록에는 P261793 본문·진행기록 고정 SELECT와, 전체 사건번호 검색에서 서버가 반환한 내부키로 바인딩하는 범용 사건 요약·사건별 문서 목록 경로를 둔다. 공유 위임계약서 문서 SELECT, UI 상세 진입과 임의 템플릿은 계속 차단한다.
- 205개 원본 열에서 권리·출원 구분, 출원일·번호, 국문 명칭, 상태 7개만 반환하는 사건 요약 투영을 구현하고 실제 P261793 읽기로 검증했다. 전화번호·메모·담당자·내부키는 제외한다.
- 세션 174의 진행기록 SELECT를 본문 `idx`와 `idx_parent`가 같은지 메모리에서 연결한 뒤 DPAPI로 저장했다. 실제 응답 2행·55열 모두 부모 식별자와 정확한 열 순서가 일치했다.
- 진행기록은 13개 업무 필드만 반환하도록 투영했다. 실제 P261793 조회에서 2건을 확인했고 첫 행의 문서 표시만 값이 있었으며 내부 행 키·부모 키·원본 55열은 반환하지 않았다.
- 과거 7건·27열 문서 목록은 서버 경로와 내부키를 숨기는 투영까지 검증했지만, 후속 검사에서 사건 문서가 아닌 공유 위임계약서 목록으로 판명됐다.
- 후속 네트워크 연결 검증에서 세션 231→245→247은 P261793 사건 문서가 아니라 `위임계약서` 공유 문서 그룹 흐름임을 확인했다. 기존 7건 목록·JPEG·OCR의 파일 무결성 근거는 보존하지만 사건 귀속은 폐기했고 실행은 실패 폐쇄한다.
- 사건 상세 로딩의 세션 9는 공유 그룹과 다른 문서 SELECT이며, `GRP_KEY`가 정확한 사건 검색에서 반환된 내부 `idx`와 일치함을 값 비노출로 확인했다. 27열·0행 기준 응답과 PT261129·PT261130의 각 0행 응답을 검증했으므로 빈 목록을 포함한 범용 사건별 문서 목록을 활성화했다.
- 범용 문서 MCP는 실제 사용자 문맥에서 PT261130의 자동 로그인·안전한 0건 목록까지 검증했다. 현재 MCP는 출원번호 검색과 OA 사건 첨부 묶음 조회를 포함한 범용 9개 도구를 협상하며 업로드 경로·내부키·원본 행은 반환하지 않는다.
- PT261268 `위임계약서 (x)`는 정확 사건 검색 → 진행행 `idx` → 중간 조회 `idx_parent` → 문서 `GRP_KEY`의 5건 SELECT 연결을 실제로 검증했다. 새 세션 17459 첨부 SELECT는 1건을 반환했고 닫은 뒤 다시 연 세션 17613에서도 같은 결과를 확인했다.
- PT261268 첨부 `PT261268외1_수임내역서.pdf`를 UI 없이 직접 HTTPS로 다운로드했다. 221,610바이트, `application/pdf`, PDF 시그니처와 SHA-256을 검증했으며 기존 파일 덮어쓰기·자동 재시도·서버 수정은 없었다.
- 다운로드 PDF는 2쪽 전체를 렌더링해 확인했고 내장 텍스트에서 표 10개 필드, 요청 건수, 생성 접두사와 관련 사건번호를 구조화했다. 이메일·전화번호·주소·전체 원문은 반환하지 않는다.
- 같은 진행항목 체인은 P261793에서도 5건의 내부 연결 검증을 통과했고 문서 0건을 정상 반환했다. 양수 결과 PT261268과 빈 결과 P261793의 교차 검증을 근거로 범용 진행항목 첨부 목록을 활성화했다.
- 상세 진입의 수정 요청 2건을 분리하고 조회 후보 3건의 지문을 확보했다.
- 캡처/결과셋 판독기, 지문 검증, 내부키 대조 도구를 구현했다.
- 고정 SELECT 클라이언트는 등록된 SQL 지문과 전체 사건번호를 확인해 요청을 만든다.
- HTTPS 전송은 인증서 검증, 고정 URL·POST, 15초 전체 제한, 2MiB 응답 제한을 적용한다. 리다이렉트와 자동 재시도는 하지 않는다.
- 읽기 템플릿과 자격 증명 없는 인증 템플릿을 Windows 현재 사용자 DPAPI 저장소로 이관하고 복호화 후 지문 일치를 확인했다. 저장소·세션 공급기·HTTPS 클라이언트를 `src/runtime.mjs`로 연결했다.
- **현재 운영 활성 범위는 전체 당소관리번호 기반 사건 요약, 사건별 진행기록·문서 목록, 진행항목별 첨부 목록, OA 사건 첨부 묶음 조회, 검증된 첨부 다운로드와 로컬 PDF 업무필드 추출이다.** 쓰기·수정 기능과 자동 재시도는 비활성이다.
- 범용 사건번호 파서는 `T`, `PT`, `PPT`, `P`, `D` 전체 문자열과 `-S1`, `-CN`, `-CN(PA)` 같은 접미사를 그대로 보존한다. 검색 건수와 결과가 각각 정확히 1이고 `ourref`가 완전히 일치할 때만 서버 내부키를 메모리에 보관해 후속 SELECT를 바인딩한다.
- 범용 사건 요약은 P261793 기준 검증과 비기준 사건 PT261129·PT261130 검증을 모두 통과했다. 과거 첫 MCP 시도는 실패했지만 실제 사용자 DPAPI·운영 바인딩 정비 뒤 v2 검증에서 PT261130의 7개 안전 필드 조회가 성공했으며, 자동 재시도·서버 수정·원본 행 또는 내부키 반환은 없었다.
- 인증 후보 세션 29의 본문 없는 POST와 Set-Cookie, 세션 32의 전체 5문장 요청과 5개 응답을 기존 캡처에서 연결했다. 같은 성공 조건을 실제 자동 로그인에서도 확인했다.
- 오프라인 다중 응답 검사기는 열 이름·타입만 반환한다. 업무 조회 클라이언트는 알려진 비밀번호·토큰 계열 열이 포함된 결과를 거부한다. 범용 개인정보 탐지나 인증 성공 검증은 아니다.
- 기존 세션 32의 SQL1을 로컬에서 확인해 사용자 ID와 `T1.pw = dbo.EncryptTxt(...)` 비교를 관찰했다. 실제 캡처에서 사용자 ID 2곳·비밀번호 1곳만 바꾸고 고정 리터럴 4개를 보존하는 오프라인 검증을 완료했다. 성공 경로는 실제 검증했지만 실패 응답 의미와 갱신은 미검증이다.
- `JSESSIONID; Path=/; Secure; HttpOnly` 구조와 기존 세션 29 응답→32 요청의 쿠키 값 일치를 로컬에서 확인했다. 쿠키 값은 프로젝트에 저장하거나 새 서버 요청에 재사용하지 않았다. 만료시간·인증 완료·갱신은 미확인이다.
- 인증 배치 SQL 5개 전체의 순서·구조와 사용자 ID 3곳·비밀번호 1곳 치환, 고정값 23개 보존을 실제 캡처로 오프라인 검증했다. 실제 계정 값을 제거한 템플릿만 Windows 현재 사용자 범위 DPAPI로 저장하고 지문·복호화 왕복을 확인했다.
- 로그인 입력 연결은 현재 출력 가능한 ASCII만 허용한다. 입력의 따옴표를 처리한 뒤 다시 분석해 구조·입력값·고정값의 보존을 확인한다. 일반 SQL 바인더나 서버 prepared statement가 아니다. 고정 URL·TLS 검증·무리다이렉트·무재시도 전송기와 최초 로그인 성공 어댑터는 런타임에 연결되어 있다.

## 실행

```powershell
cd easypat-automation
npm run status
npm run policy
npm test
```

위 명령은 서버 요청을 보내지 않는다. 기존 CLI의 화면 분류와 dry-run 계획은 개발 보조 기능이며 운영 자동화 경로가 아니다.

OA 사건 첨부 원본 경로를 직접 검증하려면 승인 목록의 사건만 다음 명령으로 실행한다. 사건 검색·진행행·첨부 집계·사건 첨부 목록을 5회 읽고, 연속된 통지 패키지의 안전 메타데이터만 반환한다.

```powershell
npm run validate-live-oa-attachment-source -- --matter-reference P261487 --progress-document 의견제출통지서
```

운영 MCP의 다섯 사건 조회와 다운로드 dry-run은 다음 명령으로 검증한다. 두 명령 모두 파일 GET·ZIP 생성·intake 쓰기·운영 DB 쓰기를 하지 않는다.

```powershell
npm run validate-live-notice-attachment-mcp
npm run validate-live-notice-download-preview
```

검증된 OA 한 건의 실제 패키지를 수동 실행하고 게시 결과를 독립 검증할 때는 전체 당소관리번호와 OA 차수를 지정한다. 실행 명령은 서버 목록을 다시 읽어 첨부 선택을 재검증하고, staging에서 파일 길이·시그니처·SHA-256과 최종 ZIP의 목록·비ASCII 항목명 UTF-8 플래그·추출본 해시를 확인한 뒤 고정 intake 폴더에 덮어쓰기 없이 게시한다. 완료 원장이 있으면 새 파일을 만들지 않고 `duplicate`로 끝난다.

```powershell
npm run download-notice-package -- --matter-reference P261252 --oa-sequence 1
npm run verify-notice-package -- --matter-reference P261252 --oa-sequence 1
```

`npm run mcp`는 로컬 MCP 클라이언트가 관리할 `stdio` 서버이므로 사람이 일반 터미널에서 계속 실행할 필요가 없다. Codex 사용자 설정에는 확인된 Node.js 절대 경로와 `src/mcp-server.mjs`가 등록돼 있다.

전용 자격 증명 상태는 `npm run credential-status`로 값 노출 없이 확인한다. 항목이 없으면 사용자가 로컬 터미널에서 `npm run register-credential`을 실행해 사용자명과 비밀번호를 직접 입력한다. 비밀번호는 보안 입력으로 받아 화면·명령행·파일에 남기지 않으며, 등록 도구는 기존 항목을 덮어쓰지 않는다.

## 고정 조회 클라이언트

신뢰된 로컬 코드가 `createFixedReadClient`에 정책·레지스트리·원문 공급기(`loadTemplate`)·메모리 내 세션 쿠키 공급기(`getSessionCookie`)를 연결한다. 외부 호출 입력은 템플릿 ID와 당소관리번호뿐이다. SQL·쿠키·URL을 사용자나 LLM이 입력하는 인터페이스는 제공하지 않는다.

고정 템플릿은 지문·명령·문장 수·작업 종류 외에 `boundMatterReference`와 응답 내부키 검증 규칙이 필요하다. 범용 문서 경로는 정확 검색이 반환한 내부키 한 곳만 지문 고정 템플릿의 `GRP_KEY`에 바인딩한다. 호출자가 내부키·SQL을 전달하거나 업무 OTHERS 배치를 보내는 기능은 없다.

Windows 자격 증명 관리자의 `EasyPAT/Automation` 일반 자격 증명만 읽는 모듈과 로그인 1회 제한·동시 호출 공유·만료/무효화 처리를 구현했다. 사용자가 등록한 항목은 값 비노출 상태 검사에서 확인됐고, 검증된 최초 로그인 성공 경로만 세션 공급기에 연결했다. 반복 실패/만료 뒤에는 공급기 수명 동안 로그인 횟수를 자동 초기화하지 않는다. 세션 갱신 규격은 후속 검증 대상이다.

암호화 저장소와 자격 증명 브로커에는 PowerShell 7(`pwsh.exe`)이 필요하다. PATH에 없으면 신뢰된 설치 경로를 `EASYPAT_PWSH_PATH`에 지정한다. 실행 정책을 변경하거나 우회 옵션을 사용하지 않는다. Windows DPAPI는 현재 사용자 범위이며 같은 Windows 계정의 프로그램에 대한 격리를 보장하지 않는다.

## 개발 중 캡처 검사

Fiddler 루트 인증서는 프로젝트가 종료될 때까지 삭제·신뢰 해제·Reset하지 않는다. 프로젝트 종료 후에도 삭제나 신뢰 해제는 사용자의 별도 승인을 받은 뒤에만 수행한다. 캡처 방식 전환을 위한 System Proxy 토글은 가능하지만 인증서 신뢰 상태와는 분리해 다룬다.

`scripts/Inspect-FiddlerClipboard.ps1`은 UI에서 관찰·복사한 특정 기존 캡처를 검사한다. 일반 사용자용 조회 명령이 아니다. 원문은 UTF-8 표준입력으로 전달하며 프로젝트에 저장하지 않는다. 내부값 대조용 해시는 민감한 파생값일 수 있으므로 작업 메모리에서만 비교하고 영구 기록에는 필드명과 일치 여부만 남긴다.

세션 245 문서 그룹 조사에는 `scripts/Inspect-DocumentGroupClipboard.ps1`을 PowerShell 7로 실행한다. 명령을 먼저 실행한 다음 안내에 맞춰 Fiddler의 **기존 세션 245 요청 Body → 응답 Body**를 차례로 복사하고 확인 창의 확인을 누른다. 복사한 내용을 PowerShell 창에 붙여넣지 않는다. 각 단계는 클립보드 원문을 출력하지 않고 UTF-8 표준입력으로 보내며 서버 요청은 없다. 요청은 DPAPI로만 저장하고 응답 원본 행은 저장하지 않는다. 이 도구는 문서 연결 후보를 조사할 뿐 운영이나 MCP를 활성화하지 않는다.

2026-09-16 검사에서 이전 `document-group-intermediate.v1`은 복호화·지문 검증에는 성공했지만 SQL이 아닌 shell 문법을 포함하고 FROM 절이 없는 것으로 확인됐다. 이전 수집기의 임의 접두사 제거를 폐기하고 새 수집은 **v2**에만 저장한다. v1 암호화 파일과 메타데이터는 수정·삭제하지 않으며 연결 근거로 사용하지 않는다. `diagnose-stored-document-request.mjs --legacy-v1`은 구형 자료의 형식 플래그만 진단한다.

응답 `parse-response` 실패에는 이제 구분자 수·행 너비·고정 오류 코드만 포함한 `inputDiagnostic`이 나온다. PowerShell 파이프가 덧붙인 마지막 줄바꿈 한 개는 전체 엄격 파서가 성공하는 경우에만 제거한다. 그 외 임의 행 건너뛰기, 탭을 구분자로 추정 변환하기, 마스킹 값 복원은 하지 않는다. 실제 실패에 사용된 입력을 진단하기 전에는 줄바꿈이 원인이라고 단정하지 않는다.

v2 중간 요청·응답 수집 뒤에는 `scripts/Inspect-DocumentGroupProgressBridge.ps1`로 기존 세션 174와 245의 Response Body를 차례로 검사한다. 진행기록 요청의 사건 부모키, 세션 245 요청의 `idx`, 두 응답의 동일 진행행, 문서 요청의 `GRP_KEY`를 모두 메모리에서 비교한다. 정확히 한 행으로 이어지는 경우에만 열 이름과 행 개수 증거를 저장하며 내부값·원본 행은 저장하지 않는다. 이 기준 검증만으로 다른 사건의 행 선택 규칙이나 MCP 운영을 활성화하지 않는다.

## MCP 도구

등록된 `easypat` 서버는 다음 도구만 제공한다.

- `easypat_status`: 서버 요청 없는 준비 상태
- `easypat_get_matter_summary`: 전체 당소관리번호로 사건 요약 7개 허용 필드 조회
- `easypat_search_by_application_number`: 출원번호 전체 문자열로 정확히 일치하는 사건의 5개 허용 필드 조회
- `easypat_list_progress`: 전체 당소관리번호 기반 진행기록 13개 허용 필드
- `easypat_list_documents`: 전체 당소관리번호 기반 사건별 문서 메타데이터
- `easypat_list_progress_documents`: 전체 당소관리번호와 진행항목명으로 해당 첨부 메타데이터 조회
- `easypat_list_notice_attachments`: 전체 당소관리번호, 통지 종류와 선택적 통지일·진행번호로 사건 첨부 저장소의 해당 통지 묶음 조회
- `easypat_download_progress_document`: 최신 목록을 다시 검증한 뒤 선택한 첨부를 동일 출처에서 다운로드
- `easypat_extract_progress_document_pdf`: 로컬 다운로드 PDF에서 허용된 업무 표 필드만 추출

과거 P261793 고정 JPEG 다운로드·OCR 도구 2개는 범용 진행항목 첨부 기능으로 대체되어 MCP 공개 목록에서 제거했다.

국내사건의 `추가 → 문서보고일 → 담당자 → 보고서류 → 파일 업로드 → 저장` 작업은 현재 안전한 준비·프로토콜 계층까지 구현되어 있다. 문서보고일은 한국시간 오늘, 담당자는 장진태를 기본값으로 표시하며 EasyPAT 표시값과 정확히 같은 `특허 출원 진행 요청`과 `의견서 및 보정서 제출 요청`, 고정 staging 폴더의 PDF만 허용한다. 파일 시그니처·크기·SHA-256·경로 이탈·중복을 검사하고, 활성화 후에는 10분짜리 단일 사용 승인으로 전체 입력과 파일 해시를 묶는다. PPT251365의 격리된 0바이트 TXT 시험으로 진행 INSERT, 별도 `/servlet/UploadExecute` multipart 전송, 날짜별 서버 상대경로 응답, 첨부 INSERT, 감사이력, 재조회 순서를 확인했지만 이 시험은 PDF 운영 검증으로 계산하지 않는다. PDF 첨부 재조회 검증과 서로 다른 사건 2건의 실검증 전까지 commit과 MCP 노출은 비활성이다. 상태는 `npm run domestic-report-upload-status`로 확인한다.

사건 기반 입력 스키마는 `P`, `PT`, `PPT`, `T`, `D` 계열의 전체 당소관리번호만 허용하며 접미사를 보존한다. 출원번호 검색은 영문·숫자와 `.-/()` 구분자만 허용하고 SQL 와일드카드는 거부한다. 사건별 진행기록과 문서 목록은 PT261129·PT261130 교차 검증을, 진행항목 첨부 체인은 PT261268·P261793 교차 검증과 PT261268 MCP 실제 검증을 통과했다. 출원번호 검색은 P261048·P261315의 사건→출원번호→사건 역방향 일치를 검증하고 P261048에서 실제 MCP 호출까지 통과했다. OA 사건 첨부 경로는 P261048·P261315·P261487·P261489·P261610에서 운영 MCP로 다시 조회해 직접 검증했다. SQL, 쿠키, URL, 내부키와 서버 경로는 입력이나 출력에 없다.

## 다음 구현 순서

진행항목 첨부 목록·다운로드·PDF 추출, OA 사건 첨부 MCP 조회와 수동 단건 ZIP 게시를 검증했다. 남은 순서는 다음과 같다.

1. 자동 큐의 중단 복구와 여러 건 일괄 재개를 구현한 뒤, 거절결정과 2차 OA 실제 표본으로 회차·이름 규칙을 검증한다.
2. HWP·HWPX·ZIP·Office 문서의 형식별 로컬 추출기를 필요한 순서대로 추가한다. PDF 추출은 활성화됐다.
3. 실패 응답과 세션 만료·갱신 규격을 별도로 관찰한다. 자동 재시도는 검증 전까지 비활성으로 유지한다.
4. 국내사건 문서보고 업로드의 실제 요청 순서와 국내사건·담당자·보고서류 선택값을 캡처한 뒤, 서로 다른 실제 사건 2건에서 추가·파일 연결·저장·재조회 검증을 통과해야 commit과 MCP 노출을 활성화한다. 미리보기·중복 방지·일회성 승인 코드는 구현됐다.
5. 프로젝트 종료를 확인한 뒤 Fiddler의 네트워크 캡처를 끄고 임시 연결을 정리한다. 루트 인증서는 사용자의 별도 승인 전에 삭제·신뢰 해제·Reset하지 않는다. 운영 EasyPAT MCP는 Fiddler에 의존하지 않는다.

정책은 [SAFETY.md](./SAFETY.md)와 `config/safety-policy.json`, 관찰 근거는 [PROTOCOL_DISCOVERY.md](./PROTOCOL_DISCOVERY.md)를 따른다. 수정 기능은 별도 승인·미리보기·중복 방지 검증이 필요한 후속 범위다.
