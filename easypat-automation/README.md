# EasyPAT HTTPS 자동화

목표는 마우스 이동 없이 EasyPAT의 HTTPS 통신으로 사건 조회, 문서 다운로드·정보 추출을 수행하고 마지막에 업무 함수를 MCP 도구로 제공하는 것이다. Fiddler와 화면 조작은 개발 중 기존 캡처를 확인하는 용도로 사용한다.

## 현재 상태

- 자동 로그인 성공 경로는 실제 계정으로 한 번 검증했다. 고정된 HTTPS POST 2건에서 사용자 ID 일치, 권한 8행, JSESSIONID 수신을 확인했고 쿠키와 자격 증명 값은 출력·저장하지 않았다.
- 인증 어댑터는 런타임에 연결되어 있지만 한 프로세스에서 로그인은 최대 한 번이며, 실패 응답 의미와 세션 갱신은 아직 비활성이다.
- P261793 본문 조회의 통제된 시도는 실패 후 자동 재시도 없이 종료되었다. 당시 Fiddler 캡처가 꺼져 있어 실패 단계와 실제 요청 수는 확정할 수 없다.
- 내부키 응답 검증을 추가한 두 번째 통제된 시도는 자동 로그인과 SELECT 응답 수신 후 결과 파서에서 종료됐다. 기존 캡처 메타데이터로 한글 열 이름 5개와 `timestamp` 타입이 원인임을 확인해 관찰된 규격만 허용하도록 파서를 수정했다. 이 시도도 자동 재시도와 서버 수정은 없었다.
- 파서 수정 후 별도 1회 게이트로 다시 검증해 1행·205열 응답과 고정 SELECT 조건의 `idx`가 정확히 일치함을 확인했다. 원문 행·내부키·쿠키는 반환하거나 저장하지 않았다.
- 운영 허용 목록에는 실제 응답 동일성을 검증한 P261793 본문·진행기록·문서 목록 SELECT 세 건을 유지한다. 별도로 범용 사건 요약은 정확한 검색 건수·전체 사건번호·서버가 반환한 내부키·205열 본문 스키마를 모두 검증하는 3단계 SELECT만 활성화했다. UI 상세 진입과 임의 템플릿은 계속 차단한다.
- 205개 원본 열에서 권리·출원 구분, 출원일·번호, 국문 명칭, 상태 7개만 반환하는 사건 요약 투영을 구현하고 실제 P261793 읽기로 검증했다. 전화번호·메모·담당자·내부키는 제외한다.
- 세션 174의 진행기록 SELECT를 본문 `idx`와 `idx_parent`가 같은지 메모리에서 연결한 뒤 DPAPI로 저장했다. 실제 응답 2행·55열 모두 부모 식별자와 정확한 열 순서가 일치했다.
- 진행기록은 13개 업무 필드만 반환하도록 투영했다. 실제 P261793 조회에서 2건을 확인했고 첫 행의 문서 표시만 값이 있었으며 내부 행 키·부모 키·원본 55열은 반환하지 않았다.
- 문서 목록은 실제 7건·27열을 검증했으며 서버 경로와 내부키를 숨긴 채 문서명·등록일·파일명·크기만 반환한다. 파일명에는 P261793이 없으므로 사용자 확인 화면과 고정된 공유 문서 그룹 문맥으로만 연결한다.
- 문서 목록 2번 `P261545외_수임내역서(수정).jpg` 한 건만 운영 다운로드에 허용했다. 최신 목록 재검증과 같은 로그인 세션을 사용해 51,373바이트 JPEG를 저장하고 SHA-256·형식·크기를 확인했으며 기존 파일은 덮어쓰지 않는다.
- 다운로드 이미지의 로컬 Windows OCR을 구현했다. 4배 확대·흑백 대비 보정 후 금액 표현 4개와 업무 키워드를 구조화했고 외부 OCR 서비스로 전송하지 않았다. 이미지 본문에는 P261793이 직접 표시되지 않아 사건번호는 추출값이 아니라 검증된 소스 문맥으로 유지한다.
- 로컬 `stdio` MCP 서버를 구현하고 Codex 사용자 설정에 `easypat`으로 등록했다. 실제 사용자 문맥에서 6개 도구 협상, 자동 로그인, 문서 목록 7건과 OCR 요약 조회를 검증했다. 현재 실행 중인 작업에는 도구가 동적으로 추가되지 않으므로 새 Codex 작업에서 사용한다.
- 상세 진입의 수정 요청 2건을 분리하고 조회 후보 3건의 지문을 확보했다.
- 캡처/결과셋 판독기, 지문 검증, 내부키 대조 도구를 구현했다.
- 고정 SELECT 클라이언트는 등록된 SQL 지문과 전체 사건번호를 확인해 요청을 만든다.
- HTTPS 전송은 인증서 검증, 고정 URL·POST, 15초 전체 제한, 2MiB 응답 제한을 적용한다. 리다이렉트와 자동 재시도는 하지 않는다.
- 읽기 SQL 3건과 자격 증명 없는 인증 템플릿을 대화형 Windows 사용자 범위 DPAPI 저장소로 이관하고 복호화 후 지문 일치를 확인했다. 저장소·세션 공급기·HTTPS 클라이언트를 `src/runtime.mjs`로 연결했다.
- **현재 운영 활성 범위는 전체 당소관리번호를 입력받는 사건 요약 7개 필드 조회와 P261793 고정 진행기록·문서·다운로드다. 목표 범위는 진행기록·문서 목록·선택 파일 다운로드까지 모두 전체 사건번호 기반으로 일반화하는 것이다.** 진행기록 후보와 다운로드의 안전한 경계는 구현했지만, 0회 통신 검사에서 사건 `idx`와 문서 `GRP_KEY`의 직접 연결이 부정되어 문서 그룹 출처를 다시 탐색 중이다. 다른 사건에서의 실제 교차검증과 MCP 노출은 비활성이다.
- 다른 사건으로 확장하기 위한 1단계 오프라인 기반을 구현했다. `T`, `PT`, `PPT`, `P` 사건번호의 전체 문자열과 `-S1`, `-CN`, `-CN(PA)` 같은 접미사를 그대로 보존한다. 기존 캡처에서 검색이 4개 사건 테이블에 동일한 `LIKE '%사건번호%'` 조건을 적용하는 건수 조회와 결과 행 조회 두 SELECT임을 확인했다. 바인더는 지문이 확인된 두 템플릿의 같은 LIKE 리터럴 4곳만 함께 바꾸며, 건수가 정확히 1이고 결과도 정확히 1행이면서 `ourref`가 완전히 일치할 때만 내부 키를 `WeakMap` 메모리에 보관해 본문 SELECT를 바인딩한다. 결과는 기존 7개 안전 필드만 반환한다.
- 범용 경로는 P261793 기준 검증과 비기준 사건 PT261129·PT261130 검증을 모두 통과했다. 각 사건에서 건수 1건, 정확한 검색행 1건, 검색 내부키와 본문 응답 내부키 일치, 205열 스키마 및 7개 안전 필드 투영을 확인했다. 각 검증의 업무 SELECT는 3건이었고 자동 재시도·서버 수정·원본 행 또는 내부키 반환은 없었다. 사건 요약 MCP 입력 스키마를 전체 당소관리번호로 확장했지만 첫 MCP 실제 검증이 로컬 요약 단계에서 실패해 자동 재시도 없이 종료했고, 진단이 끝날 때까지 범용 MCP 실행은 정책으로 차단했다.
- 인증 후보 세션 29의 본문 없는 POST와 Set-Cookie, 세션 32의 전체 5문장 요청과 5개 응답을 기존 캡처에서 연결했다. 같은 성공 조건을 실제 자동 로그인에서도 확인했다.
- 오프라인 다중 응답 검사기는 열 이름·타입만 반환한다. 업무 조회 클라이언트는 알려진 비밀번호·토큰 계열 열이 포함된 결과를 거부한다. 범용 개인정보 탐지나 인증 성공 검증은 아니다.
- 기존 세션 32의 SQL1을 로컬에서 확인해 사용자 ID와 `T1.pw = dbo.EncryptTxt(...)` 비교를 관찰했다. 실제 캡처에서 사용자 ID 2곳·비밀번호 1곳만 바꾸고 고정 리터럴 4개를 보존하는 오프라인 검증을 완료했다. 성공 경로는 실제 검증했지만 실패 응답 의미와 갱신은 미검증이다.
- `JSESSIONID; Path=/; Secure; HttpOnly` 구조와 기존 세션 29 응답→32 요청의 쿠키 값 일치를 로컬에서 확인했다. 쿠키 값은 프로젝트에 저장하거나 새 서버 요청에 재사용하지 않았다. 만료시간·인증 완료·갱신은 미확인이다.
- 인증 배치 SQL 5개 전체의 순서·구조와 사용자 ID 3곳·비밀번호 1곳 치환, 고정값 23개 보존을 실제 캡처로 오프라인 검증했다. 실제 계정 값을 제거한 템플릿만 Windows 현재 사용자 범위 DPAPI로 저장하고 지문·복호화 왕복을 확인했다.
- 로그인 입력 연결은 현재 출력 가능한 ASCII만 허용한다. 입력의 따옴표를 처리한 뒤 다시 분석해 구조·입력값·고정값의 보존을 확인한다. 일반 SQL 바인더나 서버 prepared statement가 아니다. 고정 URL·TLS 검증·무리다이렉트·무재시도 전송기와 최초 로그인 성공 어댑터는 런타임에 연결되어 있다.

## 실행

```powershell
cd easypat-automation
npm run status
npm run policy
npm test
```

위 명령은 서버 요청을 보내지 않는다. 기존 CLI의 화면 분류와 dry-run 계획은 개발 보조 기능이며 운영 자동화 경로가 아니다.

`npm run mcp`는 로컬 MCP 클라이언트가 관리할 `stdio` 서버이므로 사람이 일반 터미널에서 계속 실행할 필요가 없다. Codex 사용자 설정에는 확인된 Node.js 절대 경로와 `src/mcp-server.mjs`가 등록돼 있다.

전용 자격 증명 상태는 `npm run credential-status`로 값 노출 없이 확인한다. 항목이 없으면 사용자가 로컬 터미널에서 `npm run register-credential`을 실행해 사용자명과 비밀번호를 직접 입력한다. 비밀번호는 보안 입력으로 받아 화면·명령행·파일에 남기지 않으며, 등록 도구는 기존 항목을 덮어쓰지 않는다.

## 고정 조회 클라이언트

신뢰된 로컬 코드가 `createFixedReadClient`에 정책·레지스트리·원문 공급기(`loadTemplate`)·메모리 내 세션 쿠키 공급기(`getSessionCookie`)를 연결한다. 외부 호출 입력은 템플릿 ID와 당소관리번호뿐이다. SQL·쿠키·URL을 사용자나 LLM이 입력하는 인터페이스는 제공하지 않는다.

활성 템플릿은 지문·명령·문장 수·작업 종류 외에 `boundMatterReference`와 응답 내부키 검증 규칙이 필요하다. 현재 활성 템플릿은 P261793 본문·진행기록·문서 목록 SELECT 세 건이다. 다른 사건의 내부키를 자동 치환하거나 업무 OTHERS 배치를 보내는 기능은 없다. 지문만으로 원문을 재구성할 수 없다.

Windows 자격 증명 관리자의 `EasyPAT/Automation` 일반 자격 증명만 읽는 모듈과 로그인 1회 제한·동시 호출 공유·만료/무효화 처리를 구현했다. 사용자가 등록한 항목은 값 비노출 상태 검사에서 확인됐고, 검증된 최초 로그인 성공 경로만 세션 공급기에 연결했다. 반복 실패/만료 뒤에는 공급기 수명 동안 로그인 횟수를 자동 초기화하지 않는다. 세션 갱신 규격은 후속 검증 대상이다.

암호화 저장소와 자격 증명 브로커에는 PowerShell 7(`pwsh.exe`)이 필요하다. PATH에 없으면 신뢰된 설치 경로를 `EASYPAT_PWSH_PATH`에 지정한다. 실행 정책을 변경하거나 우회 옵션을 사용하지 않는다. Windows DPAPI는 현재 사용자 범위이며 같은 Windows 계정의 프로그램에 대한 격리를 보장하지 않는다.

## 개발 중 캡처 검사

`scripts/Inspect-FiddlerClipboard.ps1`은 UI에서 관찰·복사한 특정 기존 캡처를 검사한다. 일반 사용자용 조회 명령이 아니다. 원문은 UTF-8 표준입력으로 전달하며 프로젝트에 저장하지 않는다. 내부값 대조용 해시는 민감한 파생값일 수 있으므로 작업 메모리에서만 비교하고 영구 기록에는 필드명과 일치 여부만 남긴다.

## MCP 도구

등록된 `easypat` 서버는 다음 도구만 제공한다.

- `easypat_status`: 서버 요청 없는 준비 상태
- `easypat_get_matter_summary`: 전체 당소관리번호로 사건 요약 7개 허용 필드 조회
- `easypat_list_progress`: P261793 진행기록 13개 허용 필드
- `easypat_list_documents`: 공유 문서 그룹의 안전한 문서 메타데이터
- `easypat_download_document`: 목록 2번 JPEG만 다운로드하거나 기존 파일의 정확한 크기·SHA-256을 재검증
- `easypat_get_document_extraction`: OCR 원문을 제외한 사건번호·금액 표현·업무 키워드

사건 요약 입력 스키마는 `P`, `PT`, `PPT`, `T` 계열의 전체 당소관리번호만 허용하며 접미사를 보존한다. 현재는 첫 MCP 실제 검증 실패를 진단할 때까지 범용 사건 요약 실행을 정책으로 차단한다. 진행기록·문서·다운로드·OCR은 P261793과 허용된 위치·파일명의 리터럴 스키마로 계속 제한된다. SQL, 쿠키, URL, 내부키와 서버 경로는 입력이나 출력에 없다. 한 MCP 프로세스의 자동 로그인은 최대 한 번이고 세션 갱신은 비활성이다.

## 다음 구현 순서

문서 목록, 목록 2번 JPEG 다운로드, 해당 JPEG의 로컬 OCR은 완료했다. 남은 순서는 다음과 같다.

1. PDF·HWP·ZIP 등 다른 형식은 파일별 허용 승인을 추가한 뒤 텍스트·메타데이터 추출기를 구현한다.
2. 실패 응답과 세션 만료·갱신 규격을 별도로 관찰한다. 자동 재시도는 검증 전까지 비활성으로 유지한다.
3. 기준 사건 P261793과 비기준 사건 PT261129·PT261130의 검색→내부키→본문 연쇄 검증은 완료됐다. 첫 범용 MCP 검증 실패 뒤 실행을 차단했으며, 다음은 서버 요청이 없는 `generic-user-preflight`로 실제 사용자 DPAPI·템플릿·운영 바인딩을 진단하는 것이다.
4. 진행기록은 검색 결과의 서버 내부키를 `idx_parent` 한 곳에만 바인딩하는 범용 후보를 구현했다. PT261129와 PT261130에서 각각 1회 실제 검증한 뒤 MCP 입력을 연다.
5. 문서 목록의 기준 템플릿 검사에서 검색 `idx`와 문서 `GRP_KEY`가 다름을 확인했다. 이 직접 치환 후보는 폐기했다. 기존 암호화 템플릿끼리 문서 그룹 출처를 비교하고, 없으면 위임계약서 탭의 읽기 전용 세션 245를 검사해 서버가 반환하는 중간 그룹키를 찾아야 한다.
6. 다운로드는 일반화된 최신 문서 목록에서 사건번호·위치·예상 파일명이 일치할 때만 서버 경로를 일회성 내부 문맥으로 넘기는 안전 경계를 구현했다. 다만 문서 그룹 출처와 PT261129·PT261130 목록 검증이 완료된 뒤에만 활성화한다.
7. Fiddler의 네트워크 캡처를 UI에서 끈 뒤 임시 Fiddler MCP 연결·API 키와 필요하지 않은 루트 인증서를 정리한다. 운영 EasyPAT MCP는 Fiddler에 의존하지 않는다.

정책은 [SAFETY.md](./SAFETY.md)와 `config/safety-policy.json`, 관찰 근거는 [PROTOCOL_DISCOVERY.md](./PROTOCOL_DISCOVERY.md)를 따른다. 수정 기능은 별도 승인·미리보기·중복 방지 검증이 필요한 후속 범위다.
