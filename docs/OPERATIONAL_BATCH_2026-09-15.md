# 2026-09-15 회사 분류·감사 피드백·사건 연결 배치

## 회사와 자연인 분류

- 당사자는 `회사` 또는 `자연인`으로 구분한다.
- 회사는 별도 필드에서 `개인사업자`, `법인`, `미정` 중 하나로 관리한다. 기존 회사는 근거 없이 법적 형태를 추정하지 않고 `미정`으로 이관한다.
- 마이그레이션 적용 전 운영 DB 백업 `sspat-work-2026-09-15T06-31-34-280Z.db`을 생성했고, `006_party_classification.sql`을 적용했다.
- 사용자가 확인한 `디멘필`은 중복 회사를 만들지 않고 기존 `Demenpil Inc.` 회사 레코드를 재사용하여 `P261951-CN(PA)`의 출원인 관계에 연결했다. 회사 구분은 `미정`이다.
- 이 사용자 확인은 기존 모델 제안과 `needs_review` 검증을 덮어쓰지 않고 이벤트 `3f569056-35dd-4dc3-a17a-5efe78e12614`, 사용자 피드백, 결정 비교 이력으로 남겼다.

## 검토 피드백 구조

- `/analysis`의 사건 연결 감사와 회사·자연인 관계 감사에 `추가 확인 필요`, `확인 완료`, `대상 아님` 및 자유 입력 근거를 저장하는 폼을 추가했다.
- 사용자 답변은 원 감사 판단을 수정하지 않고 `user_feedback`, `event`, `decision_comparison`에 추가한다.
- 새 감사가 만들어져도 동일한 안정키의 과거 최신 피드백을 표시만 승계한다. 새 결정의 검토 상태는 자동으로 바꾸지 않으며, 새 감사에서 직접 입력한 답변이 우선한다.
- 본문에서 발견된 번호는 제목뿐 아니라 원문 필드와 발췌문을 함께 표시한다. URL은 동일 길이 공백으로 마스킹하여 URL 속 문자열을 사건번호로 오인하지 않으면서 원문 발췌 위치를 보존한다.
- 독립 고위험 검증이 한 번도 실행되지 않은 관계 후보는 사용자 확인으로도 반영할 수 없다. `needs_review`는 사용자의 새 근거로 확정할 수 있고, `rejected`는 새 분석이 필요하다.

## 최종 검증

- `npm ci`, lint, phase1~4 테스트, build가 모두 성공했다.
- `/`, `/mail`, `/matters`, `/analysis`, `/wiki`, `/provisional`과 필수 API 6개가 모두 HTTP 200을 반환했다.
- 새 회사 구분 API는 디멘필의 기존 `미정` 값을 중복 변경 없이 HTTP 200으로 반환했다. 감사 피드백 API는 잘못된 상태를 400, 존재하지 않는 결정을 404로 구분했다.
