# 3단계 검증 기록 — 2026-09-11

## 구현

- LLM Wiki 구조: `LLM_WIKI_DESIGN.md`. 원본/판단/확정/업무/날짜별 지식/읽기용 Wiki를 분리.
- 마이그레이션 003: 분석 후보, 입력 문맥 동결, 실제 실행 ID/결과, 근거 기반 지식 기록.
- CLI: prepare → 전문 에이전트 시작 → bind → ingest. 분석 결과를 주 작업만 검증·저장. 별도 외부 LLM API 없음.
- 화면: `/analysis`, `/matters`의 분석·검토 링크. 근거, 모델·추론·프롬프트 버전, 검토 상태, 독립 검증 결과, 수락/수정/반려.
- 상태 보호: 기존 사용자 비고/업무 상태 자동 변경 없음. 수락한 신규 Action만 업무 목록에 저장. 검토·필드별 피드백·확정 이벤트는 원자적.

## 실제 모델 표본 실행

기존 DB의 이메일 98건 중 3건(받은 메일 2, 보낸 메일 1)을 선택했다. Outlook 재수집·이동·삭제·읽음 변경은 수행하지 않았다. 전체 98건 분석 완료가 아니다.

| 동작 | 실제 모델·추론 | 결과 |
|---|---|---|
| 사실 추출 | Luna / medium | 사실 요약 후보 3개 |
| 사건 연결 검토 | Terra / high | 기존 연결 유지, 메일 3건 no_change |
| Action 판단 | Sol / high | 필요 1개, 불필요 판단 4개 |
| 독립 고위험 검증 | Sol / high | 위 8개 중 확인 5, 반려 3 |

실제 실행 4건과 결과 후보 16개(검증 결과 8개 포함)를 운영 DB에 기록했다. 검토 후보 8개는 모두 사용자 검토 대기이며 자동 확정하지 않았다. 반려된 내용은 사용자 비고·업무 상태·Action으로 반영되지 않는다.

반려 원인:

1. 인용된 과거 메일의 3건 미수 사실을 최신 메시지의 2건 보고·청구 요청 및 기한과 섞은 요약.
2. ‘수정하겠다’는 약속과 첨부 안내만으로 실제 수정 완료를 단정한 요약.
3. 과거 직접 요청이 최신 메일에서 반복되지 않았다는 이유만으로 미해결 Action을 불필요로 판정.

검증의 confirmed는 원문상 후보 지지 여부이지 법률 검증/첨부 확인/사용자 수락을 뜻하지 않는다. 이 표본에서 모델 정확도 전체를 추정하지 않는다. 프롬프트/라우팅 자동 개선은 하지 않았다.

## 자동 검증

임시 SQLite에서 1~3단계 테스트를 수행한다. 3단계는 스키마, 라우팅 불일치 거절, 디스패치 전 결과 차단, 필드별 정확한 인용, 누락 coverage, 결과 재수입 멱등성, 날짜 검증·한국 날짜, 고위험 검증 차단, 저위험이어도 검증 반려 우선, 새 메일/사용자 확정값 변경 후 재분석, 원자적 피드백·이벤트, FK·DB 무결성을 검증한다.

`npm ci`, `npm run lint`, `npm run test:phase1`, `npm run test:phase2`, `npm run test:phase3`, `npm run build` 및 localhost 주요 경로 검증을 사용한다. 테스트 가짜 모델 출력은 임시 DB에만 기록한다.

## 남은 범위

- 4단계: 사건·회사·사람·그룹별 날짜 요약 투영, Wiki 본문 생성/버전/근거 탐색, 상태 충돌·재처리 확장.
- 실데이터 전체 처리: 98건의 나머지 95건, 새 관리번호 형식/회사·사람 식별 검토. 현재 2단계의 규칙 기반 연결을 모두 검증했다고 보지 않는다.
- 반려된 표본 후보는 수정된 새 분석 실행으로 재제안할 수 있으며 기존 결과는 덮어쓰지 않는다.
