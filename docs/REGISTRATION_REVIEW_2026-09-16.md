# 2026-09-16 미등록 사건 등록 단계

## 범위와 결과

- 저장된 메일 22건에 나타난 미등록 번호 32개를 Terra/high로 검토했다. 새 Outlook 수집·이동·삭제·읽음 변경은 하지 않았다.
- 이번 배치는 **당소 사건등록 완료가 명시된 메일**로 범위를 좁혔다. 해외대리인 메일 등으로 사건 존재를 추정하는 다른 경로는 이번 단계에서 일괄 처리하지 않았다.
- T261497 1건의 전체 번호·사건등록 업로드 완료가 확인되어 Sol/high로 독립 검증했다. 내부 사건등록 완료와 상표권 등록 완료를 구분했다.
- T261497 사건 식별 레코드와 근거 메일 연결 1건을 운영 DB에 추가했다. `source_type=registration_mail`, `user_confirmed=0`, 신뢰도 0.99를 유지한다.
- 사무소·분류·국가는 기존 번호 규칙으로 상상특허·상표·KR로 기록했다. 기존 사건은 덮어쓰지 않았으며 상태·기일·담당자·회사 관계·그룹·별칭·Action은 추가하지 않았다.
- 2026-09-11 메일 기재 내용을 독립 검증된 날짜별 Wiki 관찰로 연결하고 Terra/medium으로 Wiki 1판을 게시했다. 업무 상태 확정과 구분한 문장별 근거를 유지한다.
- 후보 수락을 사용자 개별 사실확인으로 가장하지 않는다. 이번 자동 반영에서는 `user_feedback`이나 평가 성공 사례를 생성하지 않았다.

## 구현과 보호 장치

- 기존 `matter_linking` 역할에 `matterRef`와 `registrationBasis`만 가진 등록 후보 계약을 추가했다. 모델 라우팅은 변경하지 않았다.
- `applyVerifiedRegistration`은 원문 해시, 입력 메일 목록, 독립 검증자의 실행과 검증 대상, 반려·보류, 기존·보관 사건 충돌을 확인한다.
- 사본 dry-run과 운영 반영 사이에 후보·기존 데이터가 변경되면 반영하지 않는다. 등록·메일 연결·출처 관찰·이벤트는 한 트랜잭션으로 저장한다.
- 동일 후보 재실행은 새 사건·연결을 만들지 않는다. 대시보드의 일반 후보 승인 버튼으로 등록 보호 절차를 우회할 수 없다.
- 도구: `Prepare-RegistrationReview.ts`, `Operate-Registration.ts`. 사본과 운영 반영 보고서·에이전트 결과는 Git 제외 `.analysis-private/registration-review-20260916`에 보관한다.
