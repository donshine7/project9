# 우선심사신청보완요구서 자동 다운로드 기획

작성: 2026-09-21. 상태: **기획 완료, 실제 EasyPAT 관련 탭 검증과 다운로드 구현 전**.

Outlook 공통 감지 주기, 장진태 직접 수신 조건과 세 통지 종류의 중복 큐는 [Outlook 통지 메일 자동 다운로드 트리거 기획](./OUTLOOK_NOTICE_AUTO_TRIGGER_PLAN.md)을 따른다.

## 1. 목표와 범위

Outlook의 `국내특허 OA/ 우선심사 보완` 폴더에서 다음 형식의 메일을 감지한다.

```text
[업무요청] 우선심사신청보완요구서 대응 [P261643/효성프라콘 주식회사]
```

메일에서 전체 당소관리번호를 확인하고 EasyPAT의 정확한 사건을 조회한다. **관련 탭에 연결된 해당 우선심사신청보완요구서와 관계가 명확한 같은 통지 묶음만** 다운로드해 다음 폴더에 ZIP으로 게시한다.

```text
C:\Users\donsh\OneDrive\Desktop\ONEDRIVE\Desktop\[상상] 업무분류\0-0. intake\
```

권장 파일명은 다음과 같다.

```text
[당소관리번호 전체] 우선심사 보완 (n차)(통지일)(마감기일).zip
```

예상 예시는 `[P261643] 우선심사 보완 (1차)(YYYY-MM-DD)(YYYY-MM-DD).zip`이다. 차수와 날짜를 EasyPAT에서 확인하기 전에는 최종 이름을 만들지 않는다.

이 통지는 OA와 거절결정과 다른 `priority_exam_supplement_request` 종류로 관리한다. 의견제출통지서의 OA 차수나 거절결정 차수에 포함하지 않는다. 우선심사 보완 차수는 해당 사건의 `우선심사신청보완요구서` 진행행만 별도로 센다.

## 2. 현재 확인된 기반

- Outlook VBA와 정적 분류 규칙은 국내 P 사건의 `[업무요청]우선심사신청보완요구서...` 제목을 이미 `국내특허 OA/ 우선심사 보완` 폴더로 보낸다. 이번 범위에서는 메일 이동 규칙을 바꿀 필요가 없다.
- 저장된 과거 메일 표본에는 P241750-RE, P231928, P212433의 동일 업무가 있다. 최초 업무요청, `[리마인더]`가 붙은 재전송, `[EASYPAT_S]` 담당자 지정 메일과 `대응 요청` 변형을 중복·제목 회귀 표본으로 사용할 수 있다.
- 현재 EasyPAT MCP의 사건 첨부 조회는 관련 집계의 `첨부수`에서 사건 첨부 목록 SELECT를 유도한다. OA 5건에서는 검증됐지만 우선심사 보완의 관련 탭 구조가 동일하다는 실제 증거는 아직 없다.
- 현재 통지 첨부 도구의 허용 문서 종류는 `의견제출통지서`와 `거절결정서`뿐이다. 우선심사 보완은 도구 허용 목록, 선택기, 미리보기, 게시기와 원장에 추가해야 한다.

## 3. 메일 후보 생성과 중복 연결

다음 두 메일은 같은 통지 건의 서로 다른 근거가 될 수 있다.

1. 제목을 공백 정규화했을 때 `[업무요청]우선심사신청보완요구서대응` 또는 관찰된 `...대응요청` 형식인 메일
2. `[EASYPAT_S]` 담당자 지정 메일 중 본문의 `업무내용` 또는 `담당자업무`가 정확히 `우선심사신청보완요구서`인 메일

업무요청 메일을 주 트리거로 사용한다. 담당자 지정 메일은 전체 당소관리번호와 업무내용이 정확할 때 보조 근거로 연결한다. 업무요청 메일이 늦거나 누락돼도 EasyPAT 원본의 통지 종류·진행번호·통지일·기일이 모두 유일하면 담당자 지정 메일 하나로 후보를 만들 수 있지만, 메일만으로 즉시 파일을 받지는 않는다.

다음 메일은 새 통지 후보를 만들지 않는다.

- `[리마인더]`, `재요청`, `독촉`이 붙고 인용된 원문과 사건·기일이 같은 후속 메일
- 대응 방향, 번역문 또는 보완서 초안 송부 메일
- 제출 완료, 접수 완료 또는 처리 완료 메일
- 담당자 변경 메일만 있고 새로운 EasyPAT 통지가 없는 경우
- 제목이나 본문에 전체 당소관리번호가 둘 이상이거나 유효한 번호를 찾을 수 없는 경우

메일 자체는 Message-ID를 우선해 중복 제거하고, 없으면 저장소/EntryID와 정규화 내용 해시를 사용한다. 서로 다른 메일을 합칠 때는 제목의 회사명이 아니라 전체 당소관리번호와 검증된 EasyPAT 통지키를 사용한다. P241750-RE처럼 접미사가 있는 번호를 P241750으로 줄이지 않는다.

## 4. EasyPAT 관련 탭의 읽기 검증

첫 구현 단계에서는 P261643을 읽기 전용으로 조회해 다음을 확인한다.

1. 정확 사건 검색 후보를 최대 500건으로 제한한 뒤 `ourref` 전체 문자열이 P261643과 같은 한 행만 선택한다.
2. 진행기록에서 `rec_doc`가 정확히 `우선심사신청보완요구서`인 행을 찾고 진행번호, 통지일과 기일을 확인한다.
3. 관련 탭의 집계 행과 실제 첨부 목록을 대조해 UI의 어느 하위 목록이 문서를 제공하는지 확인한다.
4. 해당 첨부 목록이 현재의 사건 첨부 저장소(`DIV LIKE 'app_%'`, 검증된 사건 내부키 바인딩)와 같은지 확인한다.
5. 다른 저장소라면 임의 SQL이나 범용 탭 탐색을 추가하지 않는다. 실제 관련 탭에서 관찰한 읽기 전용 SELECT의 구조와 지문을 고정한 새 템플릿을 등록한다.
6. MCP 출력에는 서버 내부키, SQL, 쿠키와 업로드 경로를 포함하지 않는다.

P261643 확인 뒤 P241750-RE, P231928, P212433 중 EasyPAT에 남아 있는 최소 두 건을 추가로 조회한다. 총 3건 이상에서 진행행, 관련 탭의 목록 수, 본문 파일명, 등록시각과 묶음 경계를 비교한다. 과거 사건이 보존 기간이나 권한 문제로 조회되지 않으면 다른 실제 사건을 확보한다.

## 5. 통지 묶음 선택

필수 파일은 우선심사신청보완요구서 본문이다. 같은 관련 탭에 있다는 이유만으로 사건의 모든 파일을 포함하지 않는다. 다음 조건으로 해당 통지 묶음임이 확인된 파일만 선택한다.

- 본문 후보는 사건번호를 포함하고, 문서명 또는 원본 파일명이 실제 표본에서 검증된 `우선심사신청보완요구서` 형식과 일치한다.
- 본문 등록일은 EasyPAT 통지일 당일부터 7일 이내의 유일한 가장 가까운 후보여야 한다. 실제 표본에서 다른 간격이 확인되면 관찰 근거와 회귀 테스트를 추가한 뒤 범위를 조정한다.
- HDR ZIP, 특허청 `.fin`, 별지와 안내문은 등록 순서·시각과 관련 탭의 그룹 관계로 본문에 연결된 경우만 포함한다.
- 현재 OA에서 사용한 `HDR부터 본문 전후 10분의 연속 구간` 규칙을 그대로 가정하지 않는다. P261643과 교차 표본에서 같은 배치 구조가 확인될 때만 공통 선택기로 승격한다.
- 본문이 없거나 두 개 이상 동률이고, 중간에 관계를 설명할 수 없는 파일이 끼거나, 필수 원본 일부가 누락되면 전체 작업을 보류한다.

다운로드 직전에 관련 탭 목록을 다시 읽어 최초 스냅샷의 위치, 문서명, 원본 파일명, 등록시각과 파일 크기가 모두 같은지 확인한다. 변경됐으면 기존 선택 토큰을 폐기하고 같은 실행에서 자동 재시도하지 않는다.

## 6. 차수·날짜·파일명

- `supplementSequence`는 해당 사건의 `우선심사신청보완요구서` 진행행만 통지일순으로 정렬해 1부터 센다.
- 동일 진행번호와 통지일의 중복·정정 행은 한 건으로 계산한다.
- OA, 거절결정, 일반 보정요구와 우선심사결정은 이 차수에 포함하지 않는다.
- 통지일은 선택한 EasyPAT 진행행의 통지일을 사용한다. 메일 수신일이나 첨부 등록일을 대신 쓰지 않는다.
- 마감기일은 EasyPAT 진행행의 기일과 업무요청 메일의 대응기한이 일치할 때 확정한다. 한쪽이 없거나 서로 다르면 보류하며 통지일에서 날짜를 계산하지 않는다.
- 통지키는 `당소관리번호 전체 + priority_exam_supplement_request + EasyPAT 진행번호 + 통지일`이다. 표시용 차수와 마감기일은 통지키에 넣지 않는다.
- 같은 통지일에 복수 진행행이 있거나 진행번호 없이 목표 행을 유일하게 찾을 수 없으면 `supplement_sequence_unresolved`로 보류한다.

최종 파일명은 다음 함수 하나에서 생성한다.

```text
[matterReference] 우선심사 보완 (supplementSequence차)(noticeDate)(dueDate).zip
```

동명 파일이 이미 있으면 덮어쓰거나 `(1)`을 붙이지 않는다. 완료 원장과 해시가 같으면 `duplicate`, 원장과 무관하거나 해시가 다르면 `destination_filename_conflict`로 보류한다.

## 7. 다운로드·ZIP·원장

OA에서 검증한 HTTPS 다운로드 경계를 재사용한다. 동일 EasyPAT 출처, TLS 검증, 고정 업로드 경로 형식, 파일당 64 MiB와 패키지 512 MiB 제한, Content-Length 일치, 형식별 허용 MIME, PDF·ZIP 시그니처와 SHA-256을 검사한다. 자동 재시도와 EasyPAT 서버 수정은 하지 않는다.

최종 ZIP에는 다음만 포함한다.

- 검증된 우선심사신청보완요구서 본문
- 같은 통지 묶음임이 확인된 HDR ZIP, 특허청 원본, 별지와 안내문
- `download-manifest.json`

원본 파일명을 유지하고 비ASCII 항목명의 UTF-8 플래그를 검사한다. ZIP을 별도 validation 폴더에 추출해 항목명·수·크기·해시를 원본과 다시 비교한 뒤 고정 intake 폴더에 게시한다. 한 파일이라도 실패하면 완료 ZIP을 게시하지 않는다.

manifest에는 `noticeKind: priority_exam_supplement_request`, `supplementSequence`, 진행번호, 통지일, 마감기일과 원본별 이름·크기·해시·확인 시각을 기록한다. 메일 원문, 연락처, SQL, 내부키와 업로드 경로는 넣지 않는다.

원장의 `notice`에는 우선심사 보완 차수를 OA 차수와 분리해 저장한다. `notice_attachment`, `download_job`, `download_package`의 기존 버전·잠금·복구 규칙을 재사용한다. 완료 원장이 있으면 리마인더나 담당자 변경 메일이 와도 재다운로드하지 않는다. 실제 첨부가 바뀌면 기존 ZIP을 조용히 덮어쓰지 않고 새 패키지 버전 후보로 남긴다.

진행 상황은 공통 `/downloads` 화면에 종류 `우선심사 보완`으로 표시한다. 현재 `notice.notice_kind` 허용값 확장, 단계 이벤트와 화면 필드는 [통지서 자동 다운로드 대시보드 기획](./NOTICE_DOWNLOAD_DASHBOARD_PLAN.md)을 따른다.

ZIP 게시 뒤 사건 프로젝트의 폴더 생성, 보완자료 점검 작업, 사용자 증빙 제공·구성 승인과 최종검수는 [통지 종류별 대응 프로젝트 생성·진행 기획](./NOTICE_RESPONSE_PROJECT_WORKFLOW.md)을 따른다.

## 8. 실행 상태와 보류 조건

상태는 다음 순서로 진행한다.

```text
candidate → source_verified → ready → downloading → validating → published
```

다음 조건에서는 `held`로 두고 파일을 게시하지 않는다.

- 정확 사건이 0건 또는 복수
- 우선심사신청보완요구서 진행행이 없거나 복수 일치
- 진행번호·통지일·기일 또는 종류별 차수 미확정
- 메일 대응기한과 EasyPAT 기일 불일치
- 관련 탭의 실제 첨부 수와 조회 목록 수 불일치
- 본문 누락·복수 후보 또는 묶음 경계 불명확
- 다운로드 직전 목록 변경, 파일 크기·형식·해시 검증 실패
- 완료 원장과 실제 파일 불일치 또는 목적지 동명 파일 충돌
- Outlook이나 EasyPAT 세션이 사용할 수 없는 상태

Outlook 메일의 읽음 상태와 위치는 변경하지 않는다. Outlook이 종료됐으면 가장 이른 미완료 메일의 복구 지점을 유지해 다음 일자 예약 실행에서 다시 감지하며, EasyPAT 실패 요청을 같은 실행에서 반복하지 않는다.

## 9. 구현 순서

1. **관련 탭 발견:** P261643의 진행행과 관련 탭을 읽기 전용으로 확인하고 실제 첨부 SELECT·응답 스키마·본문 파일명을 고정한다.
2. **MCP 확장:** `easypat_list_notice_attachments`에 `우선심사신청보완요구서`를 허용하거나, 저장소가 다르면 목적이 한정된 별도 읽기 도구를 추가한다.
3. **메일 미리보기:** 업무요청·담당자 지정·리마인더를 하나의 통지키 후보에 연결하고 차수·날짜·예상 파일명·첨부 목록·보류 사유를 출력한다.
4. **공통 게시기 확장:** `priority_exam_supplement_request`를 명시적 허용 종류로 추가하고 종류별 파일명, manifest와 원장 필드를 연결한다.
5. **수동 dry-run:** P261643의 예상 ZIP명과 포함 파일을 표시하되 GET·ZIP·DB 쓰기를 수행하지 않는다.
