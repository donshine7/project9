# 검토함 화면

`/analysis`는 정보 확인, 변경 제안, 처리 이력의 세 메뉴로 구성한다.

- 정보 확인: 번호·당사자·그룹에 대한 질문과 근거를 표시한다. 황색 안내 및 답변 저장 버튼을 사용한다. 답변은 피드백 이력에 저장되며 사건·그룹 생성은 후속 반영 단계에서 처리한다.
- 변경 제안: 사건 연결·요약·Action·Wiki 제안을 표시한다. 청색 안내와 승인하고 반영 버튼을 사용한다. 기존 독립 검증·버전 충돌 검사와 사용자 확정값 보호를 유지한다. 검증이 필요한 항목은 보라색, 검증 반려는 적색으로 표시한다.
- 처리 이력: 현재 조회 범위에서 확인 완료·반영 완료·대상 아님·반려 항목을 표시한다. 원 제안과 현재 DB 값이 다를 수 있음을 안내한다. 최근 모델·규칙 실행 기록은 접힌 보조 영역에 둔다.

## 목록과 상세

목록은 유형, 상태, 번호, 확인할 내용, 근거 수를 보여준다. 20개씩 페이지를 나누고 검색·유형·상태 필터를 제공한다. 같은 전체 번호와 같은 검사 종류의 근거를 하나의 항목으로 묶으며, 답변은 상세에서 선택한 메일 근거에 저장한다. 서로 다른 검사 종류는 별도 질문으로 유지한다.

넓은 화면에서는 목록과 선택 항목 상세를 좌우로 배치하고, 850px 이하에서는 목록→상세→목록 전환을 사용한다. 저장 후 현재 필터·페이지를 유지하고 다음 항목을 선택한다. 새 항목 선택 시 입력 폼을 해당 항목의 기존 답변으로 초기화한다.

상세는 질문/반영할 내용, 핵심 근거, 사용자 입력, 처리 버튼 순서로 구성한다. 모델·신뢰도·원문 위치는 접어서 제공한다. 색상에는 상태 문구와 기호를 함께 사용한다.

기존 '판단과 Wiki 근거' 카드는 제거했다. 필요한 설명은 사용 방법으로, Wiki 이동은 상단 및 항목별 검색 링크로, 실행 정보는 처리 이력으로 옮겼다.

## 연결된 기능

- 기존 감사 피드백 및 후보 검토 API를 재사용한다.
- 그룹 답변은 기존 원자적 피드백 함수를 `/api/analysis/group-feedback`에 연결한다.
- Wiki의 `q` 검색 매개변수를 지원해 선택 항목에서 관련 정보를 찾을 수 있게 한다.
- 검증 과정에서 운영 사건의 수락·반려·피드백은 임의 저장하지 않는다.

## 개편 후 안정화 — 2026-09-15

- 전체 타입 검사에서 남아 있던 사건·가출원 화면의 JSON 응답 타입, 관계 피드백의 선택적 사유 SQL 바인딩, 개발 서버 타입 오류를 해결했다. `npm run typecheck`로 재검증할 수 있다.
- 사건·가출원 화면은 HTTP 실패, JSON 파싱 실패, 잘못된 최상위 응답 형태를 오류로 처리한다. 가출원 목록 조회 실패를 빈 목록의 정상 조회로 처리하지 않으며 dry-run 성공 안내에는 유효한 생성 경로가 필요하다.
- 같은 밀리초에 저장된 감사·그룹 답변은 저장 순서로 최신 값을 정한다. 표시와 중복 검사에 동일한 정렬 기준을 사용한다.
- 그룹 답변 수정 시 변경 전 값에는 직전 사용자 답변을 저장한다. 최초 답변의 변경 전 값과 원 판단은 기존대로 보존하며 과거 운영 이력을 소급 수정하지 않는다.
- 분리된 임시 DB에서 그룹·감사 답변 중복 방지, 원 판단 보존, 직전 답변 연결, 같은 시각의 최신 답변 표시, 다중 답변 중 오류 발생 시 전체 롤백을 검증했다. 운영 답변은 테스트용으로 저장하지 않았다.
- `npm ci`, `npm run lint`, `npm run typecheck`, `npm run test:client`, `npm run test:phase1`~`test:phase4`, `npm run build` 성공. 필수 화면·API 12개 HTTP 200, 운영 DB 무결성 `ok`, 실행 사본 변경 파일 11개의 해시 일치를 확인했다.

이번 단계는 코드 안정화까지다. 미등록·미지원 번호와 미완성 그룹의 확정은 사용자 답변 전까지 보류한다. 다음 운영 단계에서는 기존 저장 메일에 대한 미검증 사실 후보·반려 요약 재검토를 진행할 수 있으며, 새 Outlook 수집과 구분한다.
