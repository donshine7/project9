# 운영 데이터 반영 1차 — 2026-09-11

## 이번 실행 범위

사용자의 “다음을 진행해줘” 요청에 따라 이미 저장된 메일을 분석했다. Outlook 재수집·이동·삭제·읽음 변경은 하지 않았다. 작업 전 운영 DB 백업을 생성했다.

- 남은 95건: Luna/medium 사실 요약 후보 95건 저장. 기존 3건과 합쳐 저장 메일 98건 전체에 1차 사실 분석 결과가 있다.
- 보낸 회신을 포함한 98건: Sol/high Action 검토 결과 새 후보 5건. 독립 Sol/high 검증에서 4건 확인, 1건 사람 검토 필요.
- 이번 사실 후보 중 23건을 독립 검증: 21건 확인, 2건 반려. 나머지 72건의 독립 검증은 남아 있다. 1차 분석 완료는 전부 정확하거나 확정되었다는 뜻이 아니다.
- 단일 사건의 전체 번호가 직접 일치하는 검증된 메일 관찰 18건을 날짜별 기록으로 추가했다. 다수 사건 요약은 임의로 복사하지 않았다.
- Terra/medium으로 사건 12개의 Wiki 새 버전을 게시했다. 기존 1개를 포함해 게시된 사건 Wiki는 13개다.

후보 저장은 사용자 수락이 아니다. Action은 검토함에서 확인 후 수락해야 실제 업무 목록에 들어간다. 사용자 비고·사건 상태·담당자·기존 Action을 이번 실행에서 변경하지 않았다.

## 검증에서 차단한 사례

- 메일 ID 오기, 현재 제목 대신 인용된 과거 제목을 인용한 결과, 줄바꿈이 원문과 다른 인용: 원출력은 로컬 비공개 전송 자료로 보존하고 실패 실행 → 새 입력 스냅샷 재처리로 기록했다.
- 현재 서명 보완 요청을 최초 서명서류 요청으로, 보낸 기술 설명을 과거 고객 수정 요청으로 요약한 사실 후보 2건은 독립 검증에서 반려했다. Wiki에는 반영하지 않았다.
- 분할 여부 확인 Action에 등록마감일을 그대로 적용한 후보는 검증 보류했다. 분할 여부 확인 업무의 별도 처리기한은 사용자 확인 또는 재분석이 필요하다.
- 메일에 적힌 법적 기한·입금·출원 보고는 “메일 기재 내용”으로만 기록했다. 법정기일 검산이나 실제 납부·제출 확인을 수행한 것이 아니다.

## 사용자 확인과 코드 보강

사용자가 이번 대화에서 T는 상표 사건, -S1/-S2는 시리즈의 개별 사건, -CN(PA)는 중국 가출원이라고 확인했다. 파서·역할 지침·아키텍처·운영 지침에 반영하고 DB에 사용자 확인 이벤트와 새 근거 피드백을 기록했다. 모델이나 추론 강도는 변경하지 않았다.

전체 문자열을 먼저 추출한 다음 파싱하도록 수정했다. 미지원 접미사가 붙은 번호를 짧은 국내 사건으로 잘라 연결하지 않는다. Wiki 관찰 반영도 부분 문자열이 아니라 전체 사건번호 일치를 요구한다. 시리즈 사건만으로 그룹을 만들지 않는다.

## 검증 및 보존

- npm ci, lint, phase1/2/3/4 테스트, build 통과.
- 번호 부분 일치 차단·신규 번호 분류·기존 잘못된 연결이 있더라도 다른 사건 Wiki에 기록하지 못하는 회귀 테스트 추가.
- 로컬 주요 화면 및 API 12개 응답 200, SQLite integrity_check=ok, foreign_key_check 오류 0.
- 작업 전 백업과 비교해 mail_item, matter, work_item, assignment, action_item, matter_note, organization, person, matter_group, mail_matter_link가 동일함을 확인했다.
- 전체 실행 이력 27개: 성공 23개, 실패 4개(기존 실패 1개 포함). 준비·실행 중으로 방치된 작업은 없다.
- 운영 데이터와 전문 작업 전송 자료는 Git에 추가하지 않았다.
