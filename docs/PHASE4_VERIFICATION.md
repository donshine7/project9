# 4단계 구현·검증 — 2026-09-11

## 완료한 기능

- `/wiki`: 사건·회사·사람·그룹 선택/검색, 연결 대상 이동, 사용자 비고 편집, 최신 업무/Action 조회.
- 날짜별 중요내용 추가·정정. 정정은 새 `wiki_entry`로 추가하고 이전 근거는 유지. 발생일과 메일 날짜를 구분.
- Wiki 개정안/게시, 과거 버전 선택·좌우 비교, 문장별 근거 이벤트 → 메일 제목·일시·정확한 원문 인용 탐색.
- 입력 스냅샷과 버전 잠금: 근거·사용자 비고·업무·Action·관계가 바뀌면 오래된 초안 게시 거부.
- 메일 판단이 반려/수정되거나 검증이 변경되면 해당 관찰의 재사용 차단 및 Wiki 갱신 필요 표시.
- 실제 모델/프롬프트·입력/출력 해시·실행 ID 보존. 실패 재처리는 원본 실행을 유지하고 `retry_of`로 새 실행 연결.
- 사용자 게시/반려는 문장별 feedback/comparison/event 기록. Codex 게시를 사용자 수락이나 모델 성공 평가로 오인하지 않음.

## 모델 사용과 게시 방식

Wiki 작성은 `wiki_synthesizer` Terra/medium. 직접 API 호출이나 외부 게시 서버를 추가하지 않았다.

웹은 조회·수정·검토 화면이다. 작성/갱신은 이 프로젝트에서 요청하면 주 작업이 CLI로 입력을 준비하고 전문 에이전트의 반환을 검증한 뒤 게시한다.

사용자 확인과 독립 검증은 다르다. `wiki-capture`는 독립 검증된 사건 메일의 내용을 “메일 기재 사실”로 좁혀 기록한다. 사용자 후보 수락·실제 업무 상태 확정·Action 완료 처리를 하지 않는다. 반려 또는 사용자 수정된 원래 모델 후보는 재사용하지 않는다.

## CLI (dashboard에서)

- `npm run analysis -- wiki-capture CANDIDATE_ID MATTER_ID`: 직접 명시된 사건 + 독립 검증된 사실 후보만 관찰로 기록. 멱등.
- `npm run analysis -- wiki-prepare TYPE ENTITY_ID`: 현재 근거/업무/버전을 동결. TYPE은 matter/organization/person/group.
- `npm run analysis -- wiki-packet RUN_ID`: Wiki 작성 입력. `entry.id`가 아닌 `entry.event_id`를 인용해야 함.
- 전문 에이전트 시작 후 `npm run analysis -- bind RUN_ID AGENT_ID MODEL EFFORT`.
- `npm run analysis -- wiki-ingest JSON_PATH`: 문장별 근거·날짜·역할·개정 계약 검증. 원출력 재수입 멱등.
- `npm run analysis -- wiki-publish RUN_ID EXPECTED_DRAFT_VERSION`: 주 작업 검증 후 게시. 업무 상태 수정 없음.
- `npm run analysis -- fail RUN_ID ERROR_CODE`, `npm run analysis -- retry RUN_ID`: 실패 기록과 새 입력 재처리. 웹 재시도 버튼이 모델을 실행하는 것처럼 가장하지 않음.

## 운영 데이터 검증

운영 DB를 적용 전에 백업했다. 기존 98건을 추가 수집/일괄 분석하지 않았으며 메일 이동/삭제/읽음 변경 없음.

3단계의 P251962 사실 후보(독립 검증 confirmed)를 사건별 관찰 1건으로 연결했다. 메일 수신 날짜 2026-09-11에 특허결정서 접수 안내, 메일에 기재된 납부마감일, 분할출원 회신 요청을 기록했다. 실제 등록 완료나 법정기일 검산을 주장하지 않는다.

첫 Terra 초안은 잘못된 event ID를 사용해 저장 차단하고 `EVIDENCE_ID_MISMATCH` 실패로 기록했다. 새 실행으로 재작성한 초안은 원문/이벤트를 확인한 뒤 Wiki v1로 게시했다. 이전 실패는 삭제하지 않았다. 이는 실제 실패·재처리 경로 검증이며, 문장 정확도 전체를 보장하지 않는다.

## 자동 검증 범위

- npm ci, lint, phase1/2/3/4 테스트, build.
- 네 대상별 날짜 기록/문장 근거/게시, 잘못된 이벤트·날짜 차단, 결과 재수입/게시 멱등.
- 정정 시 과거 기록 보존, 오래된 초안 차단, 새 입력 재시도, 두 Wiki 버전 비교.
- Wiki를 포함한 백업 복구, FK/무결성 검사, 대상·날짜 조회 인덱스 사용 확인.
- localhost 주요 화면·API 응답 및 운영 Wiki 상세/근거 확인.
