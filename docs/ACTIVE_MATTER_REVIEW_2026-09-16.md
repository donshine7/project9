# 2026-09-16 현재 업무메일 기반 사건 확인

## 범위

- 앞 단계에서 남은 미등록 번호를 저장된 메일만으로 재검토했다. Outlook을 새로 읽거나 메일을 이동·삭제·읽음 처리하지 않았다.
- 사용자가 제외한 피지오 번호 15개(`PT261204`~`PT261213`, `T261435`~`T261439`)는 후보 입력에서 제외했다.
- 사건등록 완료 메일이 없더라도, 현재 메시지의 비인용 영역이 전체 당소관리번호와 실질 업무를 함께 명시한 경우만 `active_matter_mail` 후보로 허용했다.
- 사건 식별 레코드와 직접 근거 메일 연결만 반영 대상으로 삼았다. 업무종류·단계·상태·기일·담당자·회사·사람·그룹·별칭·Action은 이 근거만으로 생성하지 않았다.

## 판단 결과

- `matter_linker`를 Terra/high로 실행해 6건을 제안했다. 첫 실행은 큰 입력으로 완료되지 않아 실패 이력을 남기고, 입력을 압축한 새 실행으로 재시도했다.
- `risk_verifier`를 Sol/high로 독립 실행했다.
- 다음 4건은 현재 메시지의 직접 근거가 확인되어 운영 DB에 추가했다.

| 당소관리번호 | 분류 | 직접 근거의 성격 |
|---|---|---|
| `T251374-US` | 미국 상표 | Notice of Allowance 및 SOU 준비 안내 |
| `D261119-JP` | 일본 디자인 | 현지대리인 표의 `Your Ref.` 명시 |
| `T221357-PH(10)` | 필리핀 상표 | 제목·본문의 `Our Ref.` 명시 |
| `T241383-MD(-JP)` | 마드리드 일본 상표 | 1차 OA 및 대응 마감일 안내 |

- 4건은 모두 `source_type=mail_inference`, `user_confirmed=0`이다. 자동 판단을 사용자 확정으로 가장하지 않았고 `user_feedback`을 생성하지 않았다.
- `T261393`, `T261394`는 후보로 제안됐지만 해당 번호와 업무 설명이 현재 메시지가 아니라 인용 이력에만 있어 Sol/high 검증에서 반려했다.
- `T261395`~`T261397`, `T241383-HK`, `T241383-TW`, `T211042-MD-TH` 등은 현재 메시지의 직접 사건 존재 근거가 부족하거나 과거 인용·등록증 전달·다른 번호 형식과 섞여 있어 생성하지 않았다.
- 검증 결과의 근거 메일 ID 1건이 잘못 표기된 것을 주 작업에서 발견했다. 불변 입력 스냅샷의 실제 원문 포함 여부로 ID만 정규화하고, 원본 결과와 정규화 이력을 모두 보존했다.

## Wiki 반영

- 독립 검증된 메일 관찰을 각 사건의 날짜별 항목으로 추가하고 `wiki_synthesizer` Terra/medium으로 1판을 게시했다.
- Wiki 문구는 `메일 기재 내용`, `업무 상태 확정 아님`을 명시한다. 각 문장에 원문 인용과 메일 해시가 연결된다.
- 4개 Wiki 모두 `version=1`, `stale=false`로 실제 API에서 확인했다.

## 구현과 검증

- 등록 후보 계약에 `active_matter_mail`을 추가하고, 출처를 `mail_inference`로 분리했다.
- 원문 해시·입력 메일·독립 검증·후보 스냅샷·기존 사건 충돌을 모두 확인해야 반영되도록 했다.
- Wiki 근거는 제목뿐 아니라 본문에 전체 관리번호가 직접 나타나는 경우도 허용하되, 검증된 요약에도 같은 전체 번호가 있어야 한다.
- `npm ci`, lint, typecheck, phase1~4, 등록 전용 테스트, Outlook 규칙 회귀 테스트, build가 성공했다.
- 로컬 실행본에 변경을 동기화했고 필수 12개 화면/API가 모두 HTTP 200으로 응답했다.
