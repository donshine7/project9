합계 145건은 고유 사건 수나 확정 오류 수가 아니다. 본문의 과거 인용·외부 번호·괄호 설명이 포함된다. 기존 연결을 삭제·교체하거나 사건을 생성·병합하지 않았다. 국내 기본번호와 시리즈, 미확인 DIV 등은 별도 확인이 필요하다.

작업 중 사용자 추가 확인: -CN은 정규 중국 출원, -CN(PA)는 중국 가출원이며 가출원은 보통 우선심사용이다. 이 의미는 확정 규칙에 반영했다. 두 번호를 같은 사건의 별칭으로 자동 병합하지 않는다. 개별 메일 제목과 본문의 번호 충돌은 여전히 검토 대상이며, 개별 가출원의 우선심사용 목적도 원문 근거 없이 확정하지 않는다.

### 기존 연결 정리

기존 연결 재검토 20건을 `matter_linker` Terra/high와 독립 `risk_verifier` Sol/high로 각각 검토했다. 두 실행은 모두 입력 스냅샷·메일별 처리 결과·근거를 `decision_run`과 `decision_item`에 남겼다.

- 두 모델이 동일하게 잘못된 연결이라고 판정하고 현재 제목에 새 전체 번호가 직접 표시된 13건만 교체했다.
- 정확한 대상 사건 `P252302-CN(PA)`, `P261775-S1-CN(PA)`, `P261951-CN(PA)`, `P262000-S1` 4건을 메일 추정 사건으로 생성했다. 사용자 확정값은 아니며 신뢰도 0.99와 원본 메일을 남겼다.
- 기존 사건 레코드는 삭제·병합하지 않았다. 교체 메일의 날짜별 요약만 새 연결에 맞게 다시 만들었다.
- 모호한 기존 연결 7건은 그대로 보존했다. 사건등록 제목과 회신 본문의 `-CN`/`-CN(PA)` 불일치, 복수 시리즈 번호, 복수 중국 가출원 번호, 미확인 `-DIV1` 의미가 포함된다.
- 재감사 결과 기존 연결 재검토는 20건에서 7건으로 감소했다. 최신 전체 결과는 기존 연결 재검토 7, 연결 누락 후보 5, 미지원 형식 11, 미등록 번호 후보 96이다. 이 중 미등록 번호 후보에는 상표·외부번호·인용 이력이 섞여 있으므로 자동 생성하지 않는다.

사용자가 잔여 기준을 직접 확정했다. `-DIV1`은 원 사건의 1번째 분할출원이며 별도 사건이고, 한 메일에 관련 시리즈 사건이 여러 개이면 전체 관리번호를 모두 연결한다. 사건등록 요청과 완료 EasyPAT 번호가 충돌하면 완료된 EasyPAT 번호를 우선한다. 세 판단은 정책 이벤트와 `user_feedback`으로 보존하고 사건 연결 역할 지침과 번호 파서에 반영했다.

Sol/high가 새 사용자 근거를 적용해 잔여 6개 메일의 7개 기존 연결을 독립 검증했다. 그 결과 축약·충돌 연결 7개를 제거하고 전체번호 연결 18개를 추가했다. `P261951` 원출원 연결은 유지했다. `P261775-S1-CN`은 완료된 EasyPAT 번호 `P261775-S1-CN(PA)`와 충돌하므로 사건으로 생성하지 않았다.

- 새 메일 추정 사건 8개: `P252187-DIV1`, `P252351-CN(PA)`, `P261775-S1`~`S3`, `P261960-S1`~`S3`.
- 같은 Outlook 대화의 완료 메일을 근거로 초기 요청 메일 2개에도 `P261775-S1-CN(PA)`를 연결하고 간접 근거 유형을 별도로 표시했다.
- 최종 재감사에서 기존 연결 재검토는 0건이다. 전체 잔여 결과는 연결 누락 후보 3, 미지원 형식 10, 미등록 번호 후보 83이며 자동 생성하지 않았다.

## 회사·사람 관계

기존 `matter_linking` 계약에 회사·사람 관계 후보를 추가했다. 관리번호·대상 종류·이름·이메일·역할을 필드별로 기록한다. 메일의 전체 사건번호와 기존 사건이 일치해야 하며 회사 소속·담당자 배정은 임의로 확정하지 않는다.

- Terra/high: 선정 메일 8건을 검토하여 관계 후보 11건 저장(회사 연결 4건, 사람 연결 7건).
- 별도 Sol/high: 11건 중 10건 확인, 1건 사람 검토 필요. IRIMSO 이메일이 고하정 개인 이메일인지 확인되지 않은 후보는 수락을 차단했다.
- 피지오 의뢰인 범위, 미등록 중국 가출원 전체 번호, 제목만으로 역할을 확정하기 어려운 항목은 관계를 만들지 않았다.
- 수락은 장진태 검토함에서만 수행한다. 수락 시 회사/사람·사건 관계·필드별 피드백·이벤트를 한 트랜잭션으로 기록한다. 같은 이메일의 다른 이름, 동명이인, 복수 동일 식별값, 분석 후 대상 변경은 자동 병합하지 않는다.

최초 저장된 11건은 모두 대기 후보였다. 이후 사용자가 “IRIMSO 명의 이메일을 고하정 님 개인 주소로 연결해도 된다”고 직접 확인했다. 이 새 근거로 고하정 사람 레코드와 P261823 고객 관계 1건을 확정하고 후보를 수락 처리했다. 기존 Sol/high의 needs_review 판정은 그대로 보존하고, 사용자 확정 이벤트와 필드별 피드백을 별도 기록했다. 새 근거에 따른 확정이므로 모델 정답 사례로 자동 집계하지 않았다. 반복 실행은 중복을 만들지 않음을 확인했다.

사용자의 다음 단계 진행 지시에 따라 독립 검증을 통과한 나머지 10건도 수락했다. 현재 회사 3개, 사람 3개와 사건 관계 11건이 확정되어 있다. 인라이플 회사 레코드는 P262056·P262057에 하나를 재사용했고, 오나연 사람 레코드는 P262056~P262060에 하나를 재사용했다. P262058~P262060의 구체적인 자회사명은 확정하지 않았다. 각 후보의 수락·필드별 피드백·확정 이벤트를 별도 트랜잭션으로 기록했다.

**현재 관계 후보 11건 모두 수락 완료다.** 이 가운데 10건은 Sol/high 독립 검증 확인, 고하정 1건은 사용자 새 근거로 확정했다. 관계 추가 외에 기존 비고·업무·Action·Wiki를 변경하지 않았다. 98건 전체의 회사·사람 추출 완료나 미검증 사실 72건의 검증 완료를 의미하지 않는다.
